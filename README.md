# ShotLab AI · 连续训练记录与历史教练 V3.2

直接在电脑、手机和微信内置浏览器中运行的篮球投篮动作分析网页。用户选择视频后，MediaPipe 模型在浏览器本地完成姿态识别；视频不上传到 Streamlit 或项目服务器。

公网地址：<https://shotlab-ai-kai.netlify.app/#analyzer>

## 当前网页能力

- 输出完整的 `AnalysisResult 3.0`，一个数据对象驱动所有报告区块；
- 每球新建并关闭 CPU PoseLandmarker，固定每 100ms 采样，消除运行速度和上一球跟踪状态污染；
- 每个采样点同时执行原方向与镜像方向推理，整段选择关键点更完整的一路，修复人物左右侧拍摄时的模型方向偏差；
- 自动判断侧面、斜侧、正面/背面视角；前后视角仍识别动作阶段和节奏，但不强判侧视平面的肘膝髋角度、扑篮或后仰；
- 支持连续训练 Session、全部 Shot 切换，以及与上一球、第 1 球、此前 Session 平均和当前 Best Shot 的四层比较；
- 每球生成历史趋势、明确 Shot Number 的进步摘要、新出现问题、保持项和最多两个下一球重点；
- Best Shot 按可信度、问题数量、动作稳定性和训练参考区间综合评分，不把单个角度当成绝对标准；
- 详细动作调整表覆盖膝、髋、肘、躯干、手腕轨迹和动作节奏，并给出当前值、渐进目标区间、动作感觉和训练提示；
- 第 5 个中高可信度样本建立个人中位数/IQR Baseline；
- IndexedDB 最多保存 30 个训练，刷新可继续；原视频不长期保存；
- 总结拍摄质量、采样点、有效姿态帧、检测率、投篮手、可信度和关键阶段；
- 区分动作优点、最多两个优先问题、下一球两条指令及“本次不要改什么”；
- 对肘、膝、髋、躯干、手腕轨迹和节奏生成数据—解释—建议链；
- 同时展示原视频关键点叠加回放、火柴人回放、阶段标签和角度曲线；
- 训练处方包含目的、做法、组次、关注点、做对的感觉和常见错误；
- 手机端把宽表格切换为纵向指标卡，不产生页面横向溢出；
- 低可信度时停止精确角度纠正，明确提示如何复拍；
- 开发环境使用 `?debug=1` 可查看脱敏后的完整分析 JSON，线上默认不显示。

## 直接网页与 Python 专业版

`netlify-site/` 是当前给普通用户使用的直接网页：零后端、浏览器本地推理、打开链接即可使用。根目录 Python 代码保留了批量视频、文件导出和本地研究能力，它不是公网网页的运行依赖。

启动 `netlify-site/` 静态服务器后，可用本地视频跑正式 10 次报告：

```powershell
npm run repeatability -- "http://127.0.0.1:8088/?debug=1#analyzer" "C:\path\to\shot_test.mp4"
```

报告写入 `outputs/repeatability_report.json`，包含 5 次同页面、5 次新页面结果、分层哈希、统计量、分类一致率和 IndexedDB 恢复球数。测试视频与报告均在 `outputs/`，不会提交公开仓库。

左右方向回归可将同一视频制作水平镜像副本后分别运行：

```powershell
npm run viewpoint-smoke -- "http://127.0.0.1:8088/" "C:\path\to\left-or-right-view.mp4"
```

该测试输出每个关键点覆盖率、系统选择的方向校正、自动视角、有效帧、阶段和逐关节可信度。水平镜像只用于工程对称性回归，不能完全代替真实站位改变造成的遮挡测试。

发布门槛分为 Test A–E：A 同页面重复 5 次；B 新页面重复 5 次；C 远景/残缺身体只给复拍建议；D 两球比较、过度纠正和 IndexedDB 恢复；E 桌面、390px、WebKit/微信内置浏览器冒烟测试。

V3.2 保留五球 Session 浏览器测试：连续上传五个本地文件，验证 Shot 1–5、不丢历史、四层比较、动态目标、Best Shot、刷新恢复、正式总结和手机端无页面溢出。当前仓库只有一个达到中可信度的固定动作片段，因此浏览器五文件测试使用该片段的五个本地副本验证 Session 基础设施；改善、退步、过度纠正和新问题使用五组不同指标 fixture 验证。测试资产和结果不会提交公开仓库。

自动化 Test E 已覆盖 Chromium 桌面、390px 视口与 Windows Playwright WebKit 布局。Windows 的无头 WebKit 无法稳定读取本地 Blob 视频 metadata，因此真实 iPhone Safari / 微信内置浏览器选择 H.264 MP4 并完整分析一球，仍属于发布后的人工设备验收项。

## 科学性边界

研究表明，投篮距离和任务条件会改变关节组织、出手速度与动作时序，因此系统只使用训练参考区间、相对调整量和个人基线，不把单个角度写成通用标准。参考阅读：[投篮距离与运动学变化研究](https://pubmed.ncbi.nlm.nih.gov/38314460/)、[青年投篮系统综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC8005190/)。

当前仍是单摄像头二维趋势分析。左右侧、正面和背面都可以识别人和动作阶段，不代表所有角度在所有视角下同样可信：正面/背面主要用于节奏、画面轴线和左右对称趋势，肘膝髋的前后屈伸仍优先使用侧面或斜侧。系统不能可靠测量球的真实三维出射参数，也不会根据手腕姿态点伪造手指拨球、球旋转或进球结果。

## 微信边界

网页可作为外部 H5 链接在微信内置浏览器打开；真正嵌入微信小程序 `web-view` 还需要小程序主体、已备案业务域名和微信后台白名单，这是平台配置，不是前端代码能绕过的限制。

## 学习边界

Codex 可以完成工程实现、容错和测试。你至少要理解：三点夹角、关键点 visibility、二维投影误差、动作阶段规则、阈值校准和多样本方差。对机器人方向最可迁移的不是页面本身，而是“传感数据质量 → 时序特征 → 规则判断 → 可信度与验证”的完整闭环。
